**프로젝트 주제:** 개발 문서·프롬프트·코드를 정리하고 AI로 활용하는
마크다운 기반 크로스 플랫폼 노트 앱

**대상 사용자:** AI 코딩 도구를 사용하는 개인 개발자와 소규모 개발팀이며,

**해결하려는 문제:** 개발 과정에서 작성한 문서, 프롬프트, 코드 조각과 참고
자료가 여러 도구에 흩어져 다시 찾기 어렵고, AI 도구에 필요한 맥락을 매번
다시 전달해야 하는 문제

핵심 기능:

- 코드 블록과 프롬프트 정리에 적합한 마크다운 작성·미리보기

- SQLite 기반 로컬 저장과 오프라인 사용
- 로그인, 여러 기기 간 클라우드 동기화, 충돌 처리와 백업
- 선택한 문서의 공개·비공개 웹 호스팅
- 키워드·전문 검색과 RAG 기반 질의응답 및 출처 표시
- IDE와 AI 도구가 허용된 노트를 검색할 수 있는 읽기 전용 MCP
- 일반 마크다운 파일 가져오기·내보내기

두 달 동안은 작성·검색·동기화·호스팅을 먼저 완성하고, RAG와 MCP는 핵심
기능이 안정된 뒤 추가합니다. 실시간 공동 편집, 범용 오피스 기능과 자율
AI 에이전트는 이번 범위에서 제외합니다.

#### 개인별 역할

| 교육생 | 희망 진로 | 신규 프로젝트 역할 |
|---|---|---|
| 최우녕 | 백엔드 개발·전체 아키텍처 설계 | 로컬 앱·클라우드 서버의 모듈 경계, API 계약, 백엔드 핵심 기능과 통합 |
| 홍윤기 | 백엔드 서버·트래픽 처리 | 동기화·검색 요청의 캐시·비동기 처리, 부하 테스트와 모니터링 |
| 이민정 | 데이터 개발 | 문서·태그·링크·버전 데이터 모델, 인덱싱과 RAG 검색 파이프라인 |
| 김희준 | 프로젝트 매니저 | 요구사항, 백로그, 일정·위험·품질 관리, 사용자 검증과 공개 일정 |

역할은 각자의 주 학습 영역을 정한 것이며, 해당 영역만 맡는다는 뜻은
아닙니다. 모든 팀원은 한 개 이상의 기능을 화면부터 API·DB·테스트까지
구현합니다. 인증·보안, AI 연동, 화면, 클라우드 배포, 문서와 테스트처럼
담당이 애매한 작업은 일정과 작업량을 기준으로 나누고, 핵심 코드는 담당자가
아닌 팀원이 한 번 이상 리뷰하고 수정합니다.

### 5. 공통 학습과 협업 방식

- 코치가 추천한 소프트웨어 아키텍처 도서와 《클린 아키텍처》를 읽고,
  실제 모듈 경계와 의존성 방향에 적용합니다.
- SAGA는 개념과 보상 트랜잭션을 학습하되 처음부터 사용하지 않습니다.
  한 DB 트랜잭션과 Outbox로 해결할 수 없는 요구가 생길 때만 도입합니다.
- AI는 자료 조사, 코드 초안, 테스트와 문서 작성에 적극적으로 사용합니다.
- 구현 전에는 팀이 모듈 경계, 데이터 흐름과 사용할 프레임워크 방식을 먼저
  합의합니다.
- 작성자는 AI가 만든 코드를 포함해 자신이 올린 코드를 설명할 수 있어야
  합니다.
- 다른 팀원이 코드를 실행하고 리뷰하며, 핵심 모듈은 두 명 이상이 수정해
  봅니다.
- 매주 아키텍처 설명 시간을 갖고 API, DB와 권한 변경 이유를 함께
  기록합니다.

README, 커밋, 테스트, 교차 리뷰 PR과 배포 결과를 남겨 독자가 실제 학습과
기여 과정을 확인할 수 있게 합니다.

각자 최종 산출물은 앞에서 정한 두 개입니다.

### 6. 오픈소스와 판매 가능성

[2025 Stack Overflow 개발자 설문](https://survey.stackoverflow.co/2025/ai)에서는
AI 결과를 신뢰한다는 응답보다 신뢰하지 않는다는 응답이 많았고, AI가 만든
코드를 고치는 데 시간이 더 든다는 문제도 확인됐습니다. 다만
[GitHub Copilot Spaces](https://docs.github.com/en/copilot/concepts/context/spaces)와
[Pieces](https://docs.pieces.app/)처럼 개발 자료를 모으고 검색하는 제품이
이미 있어 단순한 메모 도구만으로는 경쟁하기 어렵습니다.

신규 프로젝트는 범용 메모 기능을 넓게 만드는 대신, 개발 문서·프롬프트·
코드 조각을 마크다운으로 보관하고 RAG와 MCP를 통해 다시 활용하는 흐름에
집중합니다. 일반 마크다운으로 내보낼 수 있게 하여 특정 서비스에 자료가
묶이지 않도록 합니다.

- 로컬 도구와 직접 설치형 서버는 오픈소스로 공개합니다.
- 관리형 동기화, 비공개 호스팅, 백업, 팀 권한과 감사 기록을 유료 기능
  후보로 둡니다.
- 팀이 4주간 실제 개발에 사용하지 않으면 클라우드 기능을 늘리지 않습니다.
- 외부 사용자의 재사용과 유료 사용 의향이 확인되지 않으면 판매 가능성이
  검증됐다고 판단하지 않습니다.
